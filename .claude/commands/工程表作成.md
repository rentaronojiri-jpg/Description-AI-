# 工程表作成スキル

案件フォルダの資料（見積・図面・現場写真）をすべて読み込み、**お客様提出用の工程表**（A3横・ブラウザで編集可能なHTML＋PDF）を、複数エージェントで分担して作成するスキル。
中目黒大規模改修工事（2026-09）で実際に作成・検証した手順をそのままスキル化している。

## 使い方

```
/工程表作成 <案件フォルダ or 案件名> [着工日] [期間]
```

例：
```
/工程表作成 ★現場ごと/★英進/中目黒大規模改修 2027-01-04 5か月
```

- 案件名だけなら `★現場ごと/` 配下を検索して特定する（同名・類似名が複数あるときはユーザーに確認。別案件のフォルダを混ぜない）
- 着工日・期間が未指定なら**先にユーザーへ確認**する。指示が無いままなら「仮置き」であることを明記して進め、最後の報告で必ず伝える
- 工程表チェック（`/工程表チェック`）は本スキルの手順3に組み込み済み

## 部品（すべて `工程表作成/` にある）

| ファイル | 役割 |
|---|---|
| `工程表テンプレート_編集版.html` | 編集機能つきテンプレート（バーのドラッグ・日付編集・行追加・着工日変更で自動再計算・**竣工日の入力（着工日は固定のまま全体を伸び縮みして最終日を合わせる）**・**休工日のカレンダー選択**・💾保存・印刷）。**中身は書き換えない** |
| `build_schedule.py` | state.json → 工程表HTML(+PDF)。日付・先行関係・足場計画届30日を検証して警告を出す |
| `dates_to_state.py` | エージェントが出した「日付つき工程案」→ 稼働日基準の state.json に変換 |
| `サンプル/中目黒大規模改修_state.json` | state.json の実例（92行・12工種）。形式に迷ったら参照 |

## 実行手順

作業用ファイル（変換画像・エージェントの出力md・JSON）は **scratchpad ディレクトリ**に置く。完成物だけを案件フォルダへ出す。

### 0. 前提を固める

1. 対象フォルダを確認：`Glob` で見積(PDF/HTML/xlsx)・図面・写真・過去工程表を洗い出す
2. **発注者・施工者・工事場所・見積範囲**を見積書から確定する（発注者=見積の宛名、施工者=当社。会社情報は `秘書/CLAUDE.md` が正）
3. 着工日・期間を確定（上記）。**休工日リスト**を作る：日曜は常に休工。日本の祝日（振替休日・ゴールデンウィーク含む）、年末年始（12/29〜1/3）、必要ならお盆。土曜は原則稼働（`satWork:true`）。初期値は state.json の `holidays`／`breaks` に入れるが、**完成後の追加・解除は画面の「休工日の設定」カレンダーで行える**（日付クリックで休工日の入／切、Shift＋クリックで期間を休工期間に追加）ので、引き渡し時にその旨を伝える
4. **当社見積範囲外の工事**（例：EV本体・内装新設・設備）は作業バーとして描かない。引継ぎ用マイルストーン（例「EV開口 躯体引渡し」）のみ可
5. 同名・類似の別案件（例：`★ブルさん案件/中目` はサロン案件で別物）を混ぜない

### 1. 資料読み込み（並列・読み取り専用エージェント）

資料の種類ごとに `general-purpose` エージェントを**同時に**起動し、結果をmdで保存させる。

| 担当 | 入力 | 出力 |
|---|---|---|
| 見積PDF（ページ数で2分割） | ページ画像 | `est_part1.md` `est_part2.md`：大項目記号・名称・階・明細・仕様・数量・単位・備考 |
| 見積HTML・過去見積 | HTML内の `value=`／JSデータ | `est_html.md`：数量・特記・不整合 |
| 図面 | ページ画像 | `drawing.md`：階数・面積・構造・解体範囲・設備・特記仕様・別途工事(A/B/C工事)・図面上の食い違い |
| 現状写真（12枚×コンタクトシート、1担当5枚程度） | シート画像 | `photos_N.md`：残置物・既存設備・アスベスト疑い・搬出動線・前面道路・近隣・足場条件 |

**変換のコツ（Windows環境で実証済み）**
- PDFの日本語が文字化け／空白：`pdftotext` と `pdftoppm` はCJKフォント無しで使えない。**PyMuPDF(`import fitz`)** で `page.get_pixmap(dpi=110)` して画像化する。見積PDFが画像PDFの場合もページ画像化して `Read` で読む
- HEIC写真：`pillow_heif` はDLLがブロックされることがある。**PowerShellの `System.Windows.Media.Imaging.BitmapDecoder`（WIC）** でJPG変換（最大辺1000px）→ PILで4列×3行のコンタクトシートに並べ、ファイル名を焼き込む
- 各エージェントには「読めない箇所は推測せず『判読不能』」「金額を捏造しない」「不整合は原文のまま記録」を必ず指示する
- 図面のタイトルや建具表の物件名が他案件になっていないか等、**食い違いは最後にユーザーへ報告**する

### 2. 工程案の作成（並列・3担当）

まず共通前提 `frame.md` を書く（全担当が最初に読む）：工事名・発注者・期間・稼働日・休工日・建物概要・搬出条件・見積の大項目と主要数量・**骨格スケジュール（週ごとの大枠）**・出力JSON形式。担当外の行は作らせない。

| 担当 | 範囲 | 目安行数 |
|---|---|---|
| 準備・仮設・申請 | 契約〜提出書類、届出・許可、石綿事前調査、電力・停電調整、共通仮設、外部足場、残置物搬出、産廃、現場管理 | 14〜20 |
| 解体工事 | 階別（上階→下階）の設備撤去→天井・床・壁→RC躯体、階段、EV開口、外部解体 | 24〜32 |
| 外装・防水・仕上げ | 外壁補修・塗装、屋上防水、躯体補修、足場解体、クリーニング、検査・引渡し | 16〜22 |

出力は日付つきJSON配列（`dates_to_state.py` 冒頭の形式）。`start`/`end` は稼働日に置き、マイルストーン・申請は `start=end`。`type` は `task / milestone / approval / buffer`。`dep` は先行作業id（`;`区切り）。**備考は全角20字以内・絶対日付を書かない**（着工日変更で古くなるため）。作業名は平易な日本語で、社内事情・金額・懸念は書かない。

### 3. 統合・整合・チェック

1. `base_state.json` を作る（`サンプル/…_state.json` をコピーして `meta`・`start`・`holidays`・`breaks`・`groups`・`notes`・`tasks:[]` を案件用に書き換える）。`groups` は表示順＝配列順。色は解体=赤系、外装=青、防水=紫、仮設=青緑、準備=灰青、産廃・管理=茶、検査=緑
2. `python 工程表作成/dates_to_state.py base_state.json state.json rows1.json rows2.json rows3.json`
3. `python 工程表作成/build_schedule.py state.json <一時出力>.html` で**警告0になるまで**日程を直す
4. **4視点の並列チェック**（`/工程表チェック` と同じ4役を、統合表 `plan_merged.md`(group|id|type|開始(曜)|終了(曜)|作業名|備考|先行) を渡して起動）：
   - 工程網羅：見積の全明細が工程に反映されているか、標準順序、最終工程
   - 日程整合性：先行後続、日数の妥当性、乾燥・養生、季節リスクと予備日、休工日、職種の輻輳
   - 申請・法規：下記「実証済みの注意点」。不確かな法令は「要確認」とし断定させない
   - 調達・リソース：資材リードタイム、業者手配・人員ピーク、足場の稼働効率、産廃車両、監督の立会い
5. 指摘のうち重大・共通指摘を反映 → 手順3-2〜3-3を再実行（警告0）。**全指摘は反映せず、採用/見送りを最終報告で明示**する

**実証済みの注意点（中目黒案件で実際に指摘・修正された点）**
- 足場計画届（高さ10m以上・60日以上）は**組立の30日前まで**。`build_schedule.py` が名称に「計画届」「足場」「組立」を含む行で自動検証する（行名を変えるときは注意）
- 石綿事前調査と結果報告は**解体着手前**。含有時は届出14日前と除去協議のため予備日（buffer）を置く
- 空調の**冷媒（フロン）回収は室内機撤去・電源切離しより前**
- 道路使用許可・道路占用許可は**ユニック車等の搬入より前**。誘導員は搬出入の全期間
- 特定建設作業（はつり等）の騒音・振動届は7日前。高騒音作業は平日日中のみ
- RC躯体はつり・スラブ撤去・EV開口は**構造協議完了（approval）の後**
- 足場は解体中に組替えが要る（ダクト・シャッター周り）。受水槽・棟屋の専用足場、EV開口足場の行を忘れない
- 電線近接・電柱の防護協議は足場組立の前提。給水・ガス閉栓、ボイラー（灯油）・キュービクル停止・PCB確認は設備撤去の前提
- 塗装・防水は工程間の乾燥と降雨の予備日（buffer）を入れる。季節により冬季の低温／梅雨に注意
- 残置物搬出は解体と同時進行させない。産廃は通期（マニフェスト）＋最終搬出
- 最後に「社内検査→竣工検査(approval)→是正→引渡し(milestone)」と竣工書類・写真整理、仮設撤去は最終日の1日

### 4. 出力

1. 出力先：`★現場ごと/<案件フォルダ>/工程表/`
   - `工程表_<案件名>_編集版_<YYYYMMDD>.html` ← `build_schedule.py state.json <出力> --pdf` で生成（同名の `.pdf` がA3横で同時に出る。PDFは `工程表_<案件名>_<YYYYMMDD>.pdf` にリネーム）
   - `state.json` も同じフォルダに残す（再生成・引き継ぎ用）
2. `--pdf` が使えない環境（Chrome/Edge無し）：HTMLをブラウザで開き 印刷→A3横→PDF保存を案内
3. 画像で確認：headless Chromeで画面/印刷のスクリーンショットを撮り、崩れ（列の細り・文字切れ・行の欠落）が無いか確認してから報告する
4. 案件固有の前提（着工日・範囲・未解決事項）を `memory/` に project メモとして保存し、`MEMORY.md` に1行追記する

### 5. 完了報告（必ず含める）

- 保存先・行数・工期（着工〜引渡し、稼働日数）・主要マイルストーン
- **仮置きにした前提**（着工日・範囲・休工日）と、**図面・見積の食い違い／未解決事項**
- チェックで採用しなかった指摘と理由、法令は一般実務に基づくため管轄への確認が必要な項目
- 編集方法の要点（バードラッグ、日付入力、着工日変更、竣工日の入力、休工日はカレンダーで選択、💾保存はダウンロードになる＝元の場所へ差し替え）
- 作業が一区切りなので **git push を促す一言**

## state.json の仕様（テンプレートが読む形式）

```jsonc
{
  "meta": { "name": "工事名", "place": "工事場所", "client": "発注者 御中", "contractor": "施工者（住所）",
            "person": "担当（電話）", "created": "2026年9月24日", "scope": "工事範囲の要約" },
  "start": "2027-01-04",            // 着工日。休工日ならその後の最初の稼働日が index 0
  "satWork": true,                   // 土曜稼働
  "holidays": ["2027-01-11", "..."], // 祝日など休工日
  "breaks": [["2026-12-29", "2027-01-03"]], // 休工期間(年末年始・お盆など)
  "groups": [ { "name": "準備・申請", "color": "#546e7a" } ],  // 表示順・色
  "tasks": [
    { "id": "TM-3", "group": "仮設工事", "name": "外部足場組立・メッシュシート取付", "note": "計画届の30日後に着手",
      "type": "task",                // task | milestone | approval | buffer
      "dep": "PR-10;PR-9",           // 先行作業id(任意)
      "s": 20,                       // 開始 = 着工日から数えた稼働日インデックス(0=着工日, 着工前は負数)
      "d": 9 }                       // 稼働日数(milestone/approval は 1)
  ],
  "notes": ["※ 注記1", "※ 注記2"]   // 表下部の注記(発注者向けの前提・条件)
}
```

- 画面上部の「竣工日」欄に日付を入れると、着工日は動かさず、着工日以降の作業（`s`・`d`）が比例して伸び縮みし、最後の作業がその日（休工日なら直前の稼働日）に終わる。着工前の準備（`s<0`）は動かさない。縮めすぎて先行関係が逆転した行は⚠表示になる。欄には常に現在の最終日が出る。
- 休工日は、画面の「休工日の設定」カレンダーで選べる（日付クリック＝`holidays`に追加／解除、Shift＋クリック＝`breaks`に期間追加。日曜と、`satWork:false` のときの土曜は選択不可）。休工期間の変更・まとめ入力は、同じ欄の「文字で編集」で行う。
- 日付は保存されず**稼働日インデックス**で持つ。着工日・休工日・土曜稼働を変えると全日付が休工日を避けて再計算される
- 注記には「仮置きの着工日」「範囲外の別途工事」「石綿含有時の別途協議」「構造協議後に着手」など、発注者に伝えるべき前提を書く。社内事情は書かない

## 注意事項

- 顧客情報・金額情報を含むため、**外部サービスへアップロードしない**（ローカルHTML/PDFのみ）。Artifactとして公開しない
- 見積は金額なしでも構わない。金額は工程表に載せない
- 資料に無い数量・仕様は推測で埋めず、「概算」「要確認」として報告する
- 既存の同名ファイルを上書きする前に、対象が自分の生成物か確認する
